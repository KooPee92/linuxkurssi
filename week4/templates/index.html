1. Server Cloning

I created Server B in CSC cPouta using a snapshot of my existing Linux server.

Both servers have their own IP addresses. Server A continues running the original website, while Server B hosts this read-only replica.

2. Automatic Backups

I created a Bash script that copies website files from Server A to Server B using rsync over SSH.

Cron is configured to run the backup every hour. Each backup is saved in a separate timestamped folder.

Backup location on Server B: /srv/backups/week4/

A dedicated Linux user, backuprecv, owns the backup directory. Access is restricted using SSH keys and file permissions. 

0 * * * * /home/ubuntu/viikko4/backup.sh

Backup results are recorded in a log file on Server A.

3. MariaDB Replication

Server A is the primary MariaDB server. Server B receives database changes automatically through MariaDB replication.

Binary logging is enabled on Server A. Server B uses a different server ID and has read-only mode enabled.

The Flask application on Server B uses a separate database user with SELECT permission only. It reads the replicated visitor count without modifying the database. 

SHOW REPLICA STATUS\G

4. Users and Permissions

I used separate users for different tasks. The backup user handles SSH file transfers, the replication user copies database changes, and the Flask reader can only read the counter.

Passwords, private SSH keys and database backups are kept outside the public website and GitHub.

5. Testing

I tested the MariaDB replication by increasing the visitor counter on Server A. The same value appeared on Server B.

I also refreshed the Week 4 page several times. The visitor count did not increase.

I verified two successful automatic hourly backups and restored an HTML file from a backup. The restored file matched the original.

I also rebooted Server B and confirmed that Nginx, MariaDB, Flask and Cron started correctly. Database replication continued working after the reboot.
